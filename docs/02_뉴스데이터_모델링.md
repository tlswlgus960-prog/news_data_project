# 02. 뉴스 데이터 모델링

## 1. 학습목표

이번 시간에는 다음 내용을 학습합니다.

- 크롤링한 CSV 데이터를 분석할 수 있다.
- 데이터베이스 구축에 필요한 컬럼을 설계할 수 있다.
- 논리명과 물리명을 이해할 수 있다.
- 데이터베이스 테이블 구조를 설계할 수 있다.
- CREATE TABLE을 작성하기 위한 준비 과정을 이해한다.

---

# 2. 이번 시간 학습 흐름

```
뉴스 크롤링
      ↓
CSV 확인
      ↓
컬럼 분석
      ↓
필요한 컬럼 추가
      ↓
논리명 / 물리명 작성
      ↓
자료형 결정
      ↓
테이블 설계
      ↓
CREATE TABLE
```

# 3. 우리가 만든 CSV 데이터 확인

지난 시간에는 네이버 뉴스를 크롤링하여 CSV 파일을 생성했습니다.

예를 들어 다음과 같은 데이터가 저장되어 있습니다.

| 언론사 | 순위 | 기사제목 | 기사링크 |
|--------|------|----------|----------|

이 CSV 파일을 그대로 Oracle Database에 저장할 수 있을까요?

이번 시간에는 CSV 데이터를 분석하여 데이터베이스 구조를 설계합니다.

---

# 4. CSV를 그대로 저장하면 안 되는 이유

CSV는 데이터를 저장하기 위한 파일입니다.

하지만 데이터베이스는 데이터를 관리하기 위한 구조가 필요합니다.

예를 들어 CSV에는 다음 정보만 존재합니다.

- 언론사
- 기사 제목
- 기사 링크
- 순위

하지만 데이터베이스에서는 추가 정보가 필요합니다. -> pk가 필요.

예)

- 뉴스번호
- 등록일
- 수정일(필요한 경우)
- 카테고리(확장 가능)

즉,

CSV = 데이터

Database = 데이터 + 관리 정보(프라이머리키, 등록일 수정일 등)

# 5. 컬럼 분석하기

CSV의 각 컬럼이 어떤 의미를 가지는지 분석합니다.

| CSV 컬럼 | 의미 |
|----------|------|
| 언론사 | 뉴스를 제공한 언론사 |
| 순위 | 랭킹 뉴스 순위 |
| 기사제목 | 뉴스 제목 |
| 기사링크 | 원본 기사 URL |

학생들과 함께

"이 컬럼이 왜 필요한가?"

를 생각해 봅니다.

---

# 6. 데이터베이스에는 어떤 컬럼이 필요할까?

데이터베이스에서는 데이터를 관리하기 위한 컬럼을 추가합니다.

예)

| 컬럼 | 설명 |
|------|------|
| NEWS_NO | 뉴스 고유번호 |
| PRESS_NAME | 언론사 |
| RANKING | 뉴스 순위 |
| TITLE | 기사 제목 |
| ARTICLE_URL | 기사 링크 |
| REG_DATE | 등록일 |

NEWS_NO와 REG_DATE는 CSV에는 없지만 데이터베이스에서는 매우 중요한 컬럼입니다.

---

# 7. 논리명과 물리명

데이터베이스를 설계할 때는 논리명과 물리명을 함께 작성합니다.

| 논리명 | 물리명 |
|--------|--------|
| 뉴스번호 | NEWS_NO |
| 언론사 | PRESS_NAME |
| 뉴스순위 | RANKING |
| 기사제목 | TITLE |
| 기사링크 | ARTICLE_URL |
| 등록일 | REG_DATE |

논리명은 사람이 이해하기 위한 이름이고,
물리명은 데이터베이스에서 실제 사용하는 이름입니다.

---

# 8. 자료형은 어떻게 결정할까?

각 컬럼의 데이터를 보고 적절한 자료형을 선택해야 합니다.

| 컬럼 | 예상 자료형 |
|------|-------------|
| NEWS_NO | NUMBER |
| PRESS_NAME | VARCHAR2 (문자열,가변형)|
| RANKING | NUMBER |
| TITLE | VARCHAR2 |
| ARTICLE_URL | VARCHAR2 |
| REG_DATE | DATE (데이트형)|

자료형에 대한 자세한 내용은 다음 시간에 학습합니다.

# 9. 뉴스 테이블 설계

최종적으로 다음과 같은 구조를 설계합니다.

```
TBL_NEWS (테이블명)

NEWS_NO
PRESS_NAME
RANKING
TITLE
ARTICLE_URL
REG_DATE
```

이 구조를 기반으로 Oracle 테이블을 생성하게 됩니다.

# 10. 실무에서는 어떻게 할까?

실무에서는 CREATE TABLE을 먼저 작성하지 않습니다.

일반적인 순서는 다음과 같습니다.

```
데이터 수집

↓

데이터 분석

↓

컬럼 설계

↓

자료형 결정

↓

테이블 설계

↓

CREATE TABLE
```

즉, 데이터 모델링이 먼저 수행됩니다.

# 12. 핵심 정리

- CSV는 그대로 데이터베이스가 되지 않는다.
- 데이터를 분석한 후 컬럼을 설계해야 한다.
- 데이터베이스에는 관리를 위한 컬럼이 추가된다.
- 논리명과 물리명을 함께 설계한다.
- 자료형을 결정한 후 CREATE TABLE을 작성한다.
